# Package Manifest Specification (`Package.syn`)

The `Package.syn` file is the primary declarative package manifest for a Syntra package.

---

## 📄 Manifest Anatomy

```syntra
// Package.syn - Syntra Package Manifest
package Config {
    name = "syntra_web_service"
    version = "0.1.0"
    edition = "2026"

    optimization {
        pgo = "locked"
        telemetry_mode = "sampling"
    }

    build {
        mode = "native"
        memory_domains = "strict"
    }

    network {
        tls_provider = "pure"
    }

    dependencies = [
        Dependency.version("syntra_math", "1.0.0"),
        Dependency.path("local_utils", "./libs/local_utils"),
        Dependency.git("syntra_json", "https://github.com/syntra-lang/json")
    ]
}
```

---

## ⚙️ Configuration Blocks

### 1. Root Properties
* `name`: Unique package name identifier (used in binary artifact naming and registry publishing).
* `version`: Semantic version string (`MAJOR.MINOR.PATCH`).
* `edition`: Language edition (`"2026"` or `"2025"`).

### 2. `optimization` Block
* `pgo`: Profile-Guided Optimization policy:
  * `"locked"`: Optimization is frozen against validated `profile.synlock` profiles.
  * `"profile"`: Execution actively collects and updates hot-path trace counters.
  * `"adaptive"`: Dynamic real-time tiering with the Self-Adapting Runtime (SAR).
  * `"off"`: Standard baseline compilation without PGO.
* `telemetry_mode`: Telemetry collection frequency for learning engines:
  * `"sampling"`: Low-overhead sampling (~5% overhead).
  * `"continuous"`: Comprehensive instrumentation recording all execution metrics.
  * `"off"`: Telemetry is disabled.

### 3. `build` Block
* `mode`: Target compilation format:
  * `"native"`: Stripped standalone native machine executable via Cranelift.
  * `"interpreter"`: Bytecode AST interpreter execution.
  * `"jit"`: Just-In-Time native compilation.
* `memory_domains`: Memory ownership enforcement mode:
  * `"strict"`: Verifies linear ownership and domain isolation at compile time (MEM-001..004).
  * `"permissive"`: Permits dynamic reference graphs with runtime assertions.
  * `"arena"`: Region-based arena allocation.

### 4. `network` Block
* `tls_provider`: Cryptographic TLS provider:
  * `"pure"`: Memory-safe pure cryptographic TLS 1.3 implementation.
  * `"native"`: Operating system native TLS stack (Security.framework on macOS, schannel on Windows).
  * `"rustls"`: Modern Rustls crypto backend.
  * `"openssl"`: System OpenSSL / LibreSSL library.

## 📦 Declaring Dependencies (`Dependency` Constructors)

Dependencies can be declared inside the `dependencies = [...]` array:

| Constructor | Description |
| :--- | :--- |
| `Dependency.version("name", "0.1.0")` | Sourced from official package registry with semver requirement. |
| `Dependency.path("name", "./path")` | Local directory relative to `Package.syn`. |
| `Dependency.package("name", "0.1.0", "./path")` | Versioned dependency with local directory fallback. |
| `Dependency.git("name", "https://...")` | Remote Git repository cloned over HTTPS or SSH. |
| `Dependency.gitBranch("name", "https://...", "branch")` | Remote Git repository pinned to a specific branch. |
| `Dependency.gitTag("name", "https://...", "v1.0.0")` | Remote Git repository pinned to a release tag. |
| `Dependency.gitRev("name", "https://...", "sha")` | Remote Git repository pinned to an exact commit SHA. |

Compact string format is also supported:
```syntra
dependencies = [
    "syntra_math: 1.0.0",
    "local_helpers: ./libs/helpers",
    "syntra_net: git+https://github.com/syntra-lang/net"
]
```

## 🔒 The Lockfile (`Package.lock`)

Running `syn lock` resolves all dependencies, computes SHA-256 / Murmur checksums, pins Git commit SHAs, and generates `Package.lock`:

```toml
# This file is automatically generated by Syntra package manager.
# Do not edit manually.

version = 1

[package]
name = "syntra_web_service"
version = "0.1.0"

[[packages]]
name = "syntra_math"
version = "1.0.0"
source = "registry:syntra"
checksum = "00000000000012a4"
```
